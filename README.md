# End-to-End-Real-Time-Air-Quality-Prediction-System
## Overview

This project demonstrates an end-to-end real-time streaming machine learning pipeline for monitoring and forecasting air quality (PM2.5 concentration) across multiple sensor stations. We simulate environmental sensor data using a Python Kafka producer, ingest and process the stream with PySpark Structured Streaming into MongoDB Atlas, serve deep learning inferences via a high-performance FastAPI backend, and visualize real-time trends on an interactive Streamlit dashboard.

---

## Architecture

# Real-Time Air Quality Forecasting System

An end-to-end real-time environmental monitoring and PM2.5 forecasting system developed for the **Online Stream Data Analysis (IE212)** course.

The system simulates real-time air quality sensor data from **6 monitoring stations in Ho Chi Minh City**, streams the data through **Apache Kafka**, processes it using **Apache Spark Structured Streaming**, performs 24-hour PM2.5 forecasting using **BiLSTM-MLAM deep learning models**, stores real-time data and predictions in **MongoDB Atlas**, and provides interactive visualization through **Streamlit** and a **FastAPI** backend.

---

## 🏗️ System Architecture

![System Pipeline](img/Pipeline.png)

The system consists of five main layers:

### 1. Data Simulation & Ingestion Layer — Apache Kafka

The Kafka producer:

* Simulates hourly air quality measurements for 6 monitoring stations.
* Reads data from `data/simulation_stream.csv`.
* Streams records to the Kafka topic `air_quality`.
* Simulates real-time streaming by introducing a configurable delay between records.

The streamed features include:

* PM2.5
* TSP
* O3
* CO
* NO2
* SO2
* Temperature
* Humidity

Main component:

```text
spark_kafka/producer.py
```

---

### 2. Processing & Inference Layer — Apache Spark + PyTorch

![Spark Processing Pipeline](img/Pipeline.png)

The Spark Structured Streaming consumer:

* Consumes real-time records from Kafka.
* Processes incoming data in micro-batches.
* Maintains historical measurements for each station.
* Requires a **48-hour historical window** before generating forecasts.
* Loads the corresponding pre-trained PyTorch model for each station.
* Performs real-time PM2.5 inference.
* Generates a **24-hour PM2.5 forecast**.
* Stores actual measurements and predictions in MongoDB Atlas.

Main component:

```text
spark_kafka/spark_consumer_mongodb.py
```

The forecasting models are based on **BiLSTM-MLAM (Bidirectional LSTM with Multi-Scale Local Attention Mechanism)**.

Each of the six stations has its own:

* PyTorch model
* Input scaler
* Output scaler

---

### 3. Storage Layer — MongoDB Atlas

The system uses **MongoDB Atlas** as the main real-time database.

Database:


Collections:


Stores actual air quality measurements received from the streaming pipeline.

```text

TSP
O3
```

#### `latest_predictions`

Stores the latest 24-hour PM2.5 forecasts generated by the Spark/PyTorch pipeline.

### 4. Backend API Layer — FastAPI

![FastAPI](img/API.png)

The FastAPI backend provides an API layer between MongoDB and client applications.

Main components:



```text

```

The FastAPI application can be accessed through its interactive API documentation:

```text
http://localhost:8000/docs
```

# 🤖 Forecasting Pipeline

The forecasting process uses a **48-hour historical window** to predict the next **24 hours of PM2.5 concentrations**.

For each station:

```text
48 hours historical data
          ↓
Data preprocessing
          ↓
Feature scaling
          ↓
BiLSTM-MLAM model
          ↓
Inverse scaling
          ↓
24-hour PM2.5 forecast
```

Six independent models are used:

```text
Station 1 → model_48_24_station1.pt
Station 2 → model_48_24_station2.pt
Station 3 → model_48_24_station3.pt
Station 4 → model_48_24_station4.pt
Station 5 → model_48_24_station5.pt
Station 6 → model_48_24_station6.pt
```

Each station also has its own input and output scaler:

```text
scaler_X_station_N.pkl
scaler_y_station_N.pkl
```

The system processes each station independently and produces a station-specific PM2.5 forecast.

# ⚠️ Troubleshooting

## MongoDB connection error

Make sure `.env` contains:

```env
MONGO_URI=mongodb+srv://<username>:<password>@<cluster>.mongodb.net/
DATABASE_NAME=air_quality_db
```

The application uses:

```text
air_quality_db
├── streaming_history
└── latest_predictions
```

If the API returns no data, verify that the streaming process and API use the same MongoDB URI and database name.

---

## Kafka connection error

Verify Kafka is running on:

```text
localhost:9092
```

Check the configured topic:

```text
air_quality
```

---

## Forecast not generated

The forecasting model requires:

```text
48 hours of historical data
```

for a station before generating the next:

```text
24-hour PM2.5 forecast
```

If the system reports:

```text
Station X chưa đủ 48h dữ liệu
```

continue the streaming process until enough historical records are available.

---

## Model not found

Verify that all model and scaler files exist under:

```text
models/
```

Required files for each station:

```text
model_48_24_stationN.pt
scaler_X_station_N.pkl
scaler_y_station_N.pkl
```
